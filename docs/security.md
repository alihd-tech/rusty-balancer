# Security and operational hardening (P7)

Default HTTP/1 header deadline: 10 seconds, 32 KiB buffer, 100 headers. HTTP/2: 64 concurrent streams per connection, 16 KiB header list, keepalive interval 30 seconds and timeout 10 seconds. Manual TLS handshake deadline: 10 seconds. Requests with unsupported Connection-nominated fields, CONNECT or overlong request targets are rejected. Existing body limits, route ACLs, HTTP admission, cache budgets, L4 connection/session caps and QUIC limits remain in effect. These are resource guardrails, not a comprehensive DDoS defense.

Use an unprivileged user, read-only configuration and code, private state and certificate directories, and a restrictive host firewall. The systemd unit and Docker Compose example provide optional resource limits and privilege isolation. Do not serve private files or symlink-containing roots. Local trusted administrators can reconfigure upstreams and static roots by design. Admin remains loopback-only and token authenticated; isolate the management listener from untrusted local tenants. Only enable compression and public caching on appropriate routes; avoid compressing secret-bearing responses.

Before production: generate and commit Cargo.lock, run scripts/release-check.sh on a clean host, execute load and malformed-traffic tests, review RustSec advisory results and dependencies, verify TLS/ACME and failover under real network conditions, audit static path handling and memory/resource exhaustion, and independently review the security design. Current gaps include a global accepted-socket cap for HTTP/TLS, full trusted-proxy handling, ACME/HTTP3 integration, L4 health probes, certificate expiry and transport metrics. No security certification or verified performance is claimed.

Release archives are local candidates with SHA-256 checksums. A checksum detects corruption, not publisher authenticity. Signed release artifacts, provenance and deployment promotion must be added/verified before public distribution.
