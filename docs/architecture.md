# Architecture

The CLI loads and validates TOML before binding a listener. The HTTP crate dispatches by exact hostname first, then longest segment-boundary path prefix. Each route points to a static directory or an upstream pool. Requests to a pool keep their original path and query. Static mounts strip the configured prefix.

The proxy streams request and response bodies with Hyper and reuses pooled upstream connections. It rewrites Host to the selected origin, removes connection-specific headers, and rebuilds forwarding identity headers from the direct TCP peer, or an explicitly trusted right-to-left X-Forwarded-For chain. Untrusted proxy identity headers are discarded. No automatic request replay is performed, including after a connection failure. Upstream request timeout covers obtaining response headers, not the entire response body.

The load-balancing crate owns health eligibility and per-endpoint in-flight HTTP request counters (held until the response body finishes or is dropped). Least-connections is weighted by configured endpoint capacity; consistent hashing uses a weighted virtual-node ring keyed on the immediate client's IP. Health checks run concurrently per endpoint and transition eligibility after configured consecutive successes/failures. Endpoints without active health checks start eligible but *unobserved*: readiness remains false until a valid upstream response is received. Pools with active health checks start ineligible until their success threshold is reached. Failed requests and HTTP 502/503/504 responses increment passive failures; three failures eject the endpoint for 15 seconds. There is no automatic replay of an in-flight HTTP request. Failover selects a healthy endpoint for subsequent requests, not a retry of an already forwarded request.

P0–P7 are a development baseline, not a hardened public edge. Inbound HTTP/1.1 and cleartext HTTP/2 prior knowledge are supported by Axum's server; upstream HTTP/1.1 over HTTP or verified HTTPS is intentional for this milestone. TLS termination, SNI, ALPN, ACME and optional HTTP redirects are implemented as opt-in capabilities (see [TLS](tls.md)). Traffic policies provide opt-in WebSocket upgrades, request buffering limits, rate limits, compression and bounded public caching (see [traffic policies](traffic.md)). Response body polling has an idle deadline and a global in-flight cap. A separate authenticated loopback management API swaps immutable request generations, preserves the global admission ceiling and exposes process telemetry (see [management](management.md)). Listener and TLS configuration changes require restart. Trusted-proxy boundaries are explicit and per-process; arbitrary CONNECT and socket-write deadlines remain future work. HTTP and HTTPS share an accepted-socket budget that also covers TLS handshakes. Both listeners use a 30-second graceful shutdown deadline. Never expose this baseline to untrusted public traffic. Only configure trusted upstream origins and static roots without links to sensitive files. Relative static paths resolve from the working directory.

Optional Layer 4 TCP/UDP listeners and experimental QUIC HTTP/3 ingress run beside HTTP. See [network transports](transport.md). Transport listeners are restart-only.

Release and deployment tooling is documented in [release](release.md); [security](security.md) lists limitations. Network listeners and HTTP/3 configuration require restart.
